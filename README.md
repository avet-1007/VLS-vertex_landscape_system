# VLS — Vertex Landscape System

**Полная инструкция по редактору карт.**

Это не бриф и не конспект для нейросети, а описание, написанное человеком, который этот
редактор делал: что за система, как она устроена, какие кнопки за что отвечают и почему
внутри всё именно так, а не иначе. Все примеры — из реального кода версии **V-0.1.18**.

Последний раздел — **футажи**: там по шагам расписано, что нужно сделать в редакторе и
что снять на скриншот, а строки с картинками уже вставлены в текст.

---

## 1. Что такое VLS

VLS — это **браузерный редактор карт-уровней для 2D-движка**. Карта в нём собирается не
из тайлов и не из спрайтов, а из **вершин, линий и секторов** (комнат) — то есть как
чертёж: сначала ставятся точки, из точек складываются стены, из стен замыкаются комнаты,
а внутрь комнат раскладываются лифты, существа и триггеры.

Ключевой принцип: **геометрия — это данные, а не картинка.** Каждая стена — отдельная
линия со своей текстурой и флагами, каждый сектор — список вершин. Игровой движок
получает тот же самый файл и строит по нему коллизии, поэтому редактор и рантайм не
расходятся: что ты нарисовал, то движок и получит.

Формат карты — обычный текстовый файл `.vls`. Его можно открыть в блокноте, посмотреть
глазами, поправить руками и запихнуть в git.

Что умеет редактор сейчас:

* рисование геометрии: точки, линии, замкнутые сектора, готовые прямоугольники;
* соединение соседних секторов тремя способами (свободный проход, соединение, стык);
* текстуры пола и стен, высота сектора, свойства (камень, хрупкая коробка, дверь, конец уровня);
* расстановка существ с кодами и именами;
* лифты с этажами, кривой движения и привязкой вызывалок к существам;
* триггеры-прямоугольники;
* выделение, групповые операции, копирование, отмена;
* проверки карты на ошибки;
* сохранение в браузер, загрузка и выгрузка `.vls`.

Статус: **V-0.1.18** (метка внизу окна). Это рабочая версия без сборки, зависимостей и
установки — один HTML-файл со скриптами рядом.

## 2. Как открыть редактор

1. Папка проекта: `VLS-project`.
2. Внутри — `VLS_editor.html`, рядом папка `js/` и файл `style.css`.
3. Открой `VLS_editor.html` в любом браузере двойным щелчком. Ничего устанавливать не
   нужно, интернет не нужен — всё работает локально с `file://`.

Полезное при первом запуске:

* **Язык.** По умолчанию интерфейс английский. Нажми шестерёнку в тулбаре (Настройки) →
  **Язык** → **Русский**. Выбор запоминается в браузере.
* **Журнал дублируется в консоль** — клавиша `F12` → вкладка Console. Туда пишется всё,
  что происходит с картой.
* **Карта восстановится сама.** Редактор автосохраняет её в браузере после каждого
  изменения; при следующем открытии всё на месте. Если браузер чистил localStorage —
  карта будет пустая, и тогда имеет смысл нажать «Загрузить карту» и выбрать файл `.vls`.

**Всплывающие элементы**

* **toast** — уведомление внизу, живёт 2 секунды;
* **контекстное меню** — по ПКМ по объекту: свойства, удаление, закрытие;
* **настройки** — выплывающее окно с выбором языка.

## 4. Модель карты

Карта — один объект `mapData` со счётчиком ` _idc`, из которого выдаются все новые
идентификаторы.

| Коллекция | Что это | Поля |
|---|---|---|
| `vertices` | точки чертежа | `{id, x, y}` |
| `lines` | стены (рёбра между двумя точками) | `{id, a, b, tex, flags, free?, step?}` |
| `sectors` | комнаты | `{id, verts[], floorTex, wallTex, height, flags, offset{x,y}, stone, fragile, close, finish, neighbors[]}` |
| `connects` | связи двух линий в один проход | `{id, lineId, line2Id, fromSector, toSector}` |
| `things` | существа/объекты | `{uid, id, type, name, x, y, slot, sectorId}` |
| `lifts` | лифты | `{id, sectorId, curve, sec, floors[{name,x,y,entityId?}], zeroEntityId?, zeroEntityType?}` |
| `triggers` | триггеры | `{id, tid, type, ticks, x1, y1, x2, y2}` |

Важные правила:

* **Линия всегда опирается на две точки.** Двигаешь точку — линии едут сами. Удаляешь
  точку — осиротевшие линии вычищаются.
* **Сектор — это замкнутый список точек.** Незамкнутая фигура сектором не является, и
  об этом скажут проверки.
* **Существо всегда привязано к сектору** и физически лежит в нём.
* **Лифт принадлежит одному сектору** (один сектор — один лифт).

Флаги линии (`flags`):

* `"0"` — обычная стена, коллизия;
* `"1"` — стена сектора;
* `"2"` — портал/соединение: два сегмента ведут себя как один проход;
* `free` — свободный проход (линия закрывает сектор герметично, но ходить через неё нельзя);
* `step` — стык (шов/уступ, нужен лифтам и лесенкам).

## 5. Сетка, координаты и привязка

* **Одна клетка = 40 юнитов** (`GRID_SIZE`), шаг перемещения — 20 юнитов (половина клетки).
* Привязка при установке точек идёт к самому удобному якорю: узел сетки (кратно 40),
  центр клетки (кратно 20), середина ребра сетки или **середина уже существующей линии**.
  За счёт последнего стыки получаются идеальными без ручного подсчёта.
* **Зажатый `Shift` отключает привязку** — курсор идёт точно до 1 юнита. То же `Shift`
  в режиме выделения позволяет двигать объекты по одному юниту вместо шага в 20.
* Строка координат внизу справа показывает `x`, `y` в юнитах и пару клеток `x,y`.

## 6. Инструменты

Горячие клавиши приведены в скобках. Инструменты сгруппированы в тулбаре сверху.

| Инструмент | Клавиша | Что делает |
|---|---|---|
| Точка | `P` | ставит вершину; клик по существующей линии **разрезает** её в точке клика |
| Линия | `L` | клик по вершине — начало, клик по другой — линия; клик по той же — сброс |
| Сектор | `S` | кликайте по вершинам по кругу, вернитесь на первую (их должно быть ≥3) — сектор замкнётся |
| Выделение | `V` | переключатель режима выделения (см. раздел 8) |
| Прямоугольник | `B` | протяжка ЛКМ — готовый прямоугольный сектор; **разовый** инструмент |
| Гладкие углы | `G` | то же, но со сглаженными углами; тоже разовый |
| Соединение | `C` | два клика по стенам соседних секторов; режим задаётся в панели «Соединение» |
| Лифт | `E` | клик по сектору — создать/выбрать лифт; ПКМ — добавить этаж |
| Существо | `T` | клик внутри сектора ставит существо с текущим кодом из тулбара |
| Триггер | — | зажать ЛКМ и протянуть прямоугольник |
| Выбор текстур | — | пока не работает, кнопка серая (показывает уведомление) |

Нюансы, которые не очевидны из иконок:

* **Бокс и гладкие углы — разовые.** Использовал → редактор сам вернул предыдущий
  инструмент. Клик без протяжки такими инструментами ничего не создаёт, а просто
  выделяет сектор под курсором.
* **Клик по линии инструментом «Точка»** режет линию на две — так добавляются углы в
  уже построенные стены.
* **В режиме «Сектор» клик по промежуточной выбранной точке** снимает её с выбора.
* **Триггер и бокс** создаются только протяжкой; обычный клик — это выбор объекта.

## 7. Мышь и клавиши

| Действие | Что делает |
|---|---|
| ЛКМ | действие текущего инструмента / выбор объекта / перетаскивание |
| ЛКМ по уже выделенному | тащит всю группу выделения (после попытки «провалиться» внутрь на меньший объект) |
| `Shift` + ЛКМ | добавить объект к выделению; отключить привязку к сетке |
| ПКМ-клик (без движения) | контекстное меню объекта (его свойства) |
| ПКМ-протяжка | выделить всё внутри прямоугольника — **работает в любом инструменте** |
| `~` + ПКМ-протяжка | удалить всё внутри прямоугольника |
| СКМ (средняя) — протяжка | панорамирование камеры |
| Колесо мыши | масштаб |
| Стрелки | сдвинуть выделенное на шаг (20 юнитов); при зажатом `Shift` — на 1 юнит |
| `Esc` | отменить текущую операцию, закрыть меню, выключить выделение |
| `Delete` / `Backspace` | удалить выделенное |
| `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` | отменить / повторить |
| `Ctrl+C` / `Ctrl+V` | копировать / вставить |
| `Ctrl+A` | выделить всё |

Порог для «протяжки» — примерно 6 пикселей: меньше — это клик, больше — рамка. Поэтому
выделение прямоугольником — это **один жест** (зажал → потянул → отпустил), а не два
нажатия.

## 8. Выделение

**Выделение — переключатель с парой.** Кнопка `V` (и клавиша `V`) включает режим
выделения, причём «целью» выделения становится тот гео-инструмент, который был активен
до этого: был «Сектор» — выделяются сектора, была «Точка» — вершины.

Как менять цель, не выходя из выделения: **нажмите кнопку нужного гео-инструмента** —
в режиме выделения она не переключит инструмент, а сменит тип цели. В тулбаре при этом
подсвечиваются обе кнопки — и «Выделение», и кнопка текущей цели. Повторное нажатие `V`
полностью выключает режим.

Возможности:

* клик — выбрать; `Shift`+клик — добавить к выделению;
* выделение группируется по типу: точки, линии, сектора, существа, триггеры, этажи лифтов;
* ПКМ-протяжка выделяет всё внутри рамки независимо от активного инструмента;
* `Ctrl+A` — выделить всё;
* стрелки двигают выделенное, `Delete` удаляет;
* выделенный сектор можно двигать — вместе с ним едут лежащие в нём существа;
* в панели «Существа» кнопка **«Разместить в точке выбора»** ставит существо в центр
  выделенного сектора.

## 9. Секторы и соединения

Самая важная механика: как из двух отдельных комнат сделать один проход.

Режим выбирается слева в разделе **«Соединение»** (три большие кнопки) или в выпадающем
списке рядом с инструментом «Соединение» в тулбаре — они синхронизированы.

| Режим | Как работает |
|---|---|
| **Свободный проход** | один клик по линии переключает флаг `free`. Линия закрывает сектор герметично, но через неё не ходят. Второй клик выключает флаг. |
| **Соединить** | клик по стене первого сектора, затем по стене второго. Линии должны лежать **друг на друге юнит-в-юнит**. Успех — обе линии становятся порталом (`flags = "2"`) и создаётся запись в `[connects]`. |
| **Стык** | те же два клика, но достаточно **частичного** наложения. Обе линии получают `step` — это шов/уступ, которым пользуются лифты и лесенки. |

Как понять, что получилось:

* стена подсвечивается **зелёной галочкой** — можно кликать;
* **красный крест** — линии не накладываются, соединение не создастся;
* в HUD появляется «Секторы соединены! (C#)» или ошибка
  «линии должны накладываться юнит-в-юнит».

Ограничения:

* **Линии сектора-лифта связывать нельзя** — для них разрешён только свободный проход;
* клик второй раз по той же линии, что и первая, ищет наложенную на неё линию — это
  способ соединить стены, которые уже лежат друг на друге.

## 10. Существа и система ID

Существо (`thing`) — объект внутри сектора: техника, вызывалка лифта, ключ, подбираемое,
враг. Рисуется как ромбик.

### 10.1. Категории и формат кода

Код — буква категории + три цифры, например `A007`:

* `A` — техника: вызывалки лифтов, ключи, точки вызова;
* `B` — подбираемое: оружие, боеприпасы, предметы;
* `C` — враги и NPC;
* `A000` — **зарезервирован за игроком** (точка появления), вручную не выдаётся.

### 10.2. Код — это тип, а не серийный номер

Здесь самое главное, что чаще всего понимают неправильно.

**ID отвечает на вопрос «что это за существо», а не «какой это экземпляр».** Поэтому
одинаковый код у нескольких существ — это норма, а не ошибка: три одинаковые вызывалки
на трёх этажах — это `A001`, `A001`, `A001`; десять одинаковых врагов — десять `C001`.
Редактор не запрещает повторы и ничего при этом не «обменивает местами».

Движок получает код и понимает, **с каким типом объекта работает** — у одного кода одно
поведение. Именно поэтому в файле `.vls` лежит код, и именно по коду строятся привязки
лифтов (раздел 11).

### 10.3. Внутренняя метка экземпляра

Раз код повторяется, ему нельзя доверять роль первичного ключа. Поэтому у каждого
существа есть **`uid`** — внутренняя уникальная метка:

| | Отвечает на вопрос | Уникален? | Где живёт |
|---|---|---|---|
| `id` (код) | Что это за существо | нет, повторяется | `.vls`, привязки лифтов, движок |
| `uid` (метка) | Который это экземпляр | да, в пределах карты | только редактор, **в файл не пишется** |
| `name` (имя) | Как это назвать | нет, повторяется | только отображение |

По `uid` работает всё, что трогает конкретный ромбик: выделение, рамка, перетаскивание,
удаление, копирование, отмена. Метка не зависит от кода — переименовал существо, а
выделение и привязки не слетели. При загрузке карты всем существам `uid` выдаются заново.

### 10.4. Где редактировать код и имя

Три места:

1. **Тулбар** (для новых существ) — квадратная кнопка с буквой `A` (в ней выпадающий
   список A/B/C) и поле номера рядом; кнопки `▲`/`▼` шагают на ±1. Имени в тулбаре нет.
2. **Левая панель «Существа»** (для выбранного) — поля **Код** (буква + номер + `▲`/`▼`)
   и **Имя**; `Enter` или кнопка применения — применить.
3. **Контекстное меню (ПКМ по существу)** — те же поля `Код` и `Имя`, плюс позиция и
   номер сектора. В поле номера работают и стрелки `↑`/`↓` (шаг ±1).

Поведение полей:

* номер принимает 1–3 цифры (`5` → `005`) или код целиком (`B012`), пробел допустим
  (`A 001`);
* `▲`/`▼` и стрелки идут ровно на 1 и **проходят через занятые номера** — повторы
  разрешены, блокировок нет;
* на `A000` перейти нельзя — это зарезервированный код игрока;
* при смене кода **привязки лифтов, хранящие прежний код, переезжают на новый**
  автоматически;
* имя, оставшееся равным старому коду, обновляется следом за кодом;
* **✕ «Перевыдать»** в панели — для битого кода (неверный формат). Занятый код
  перевыдавать не нужно: он не битый.

### 10.5. Принадлежность к сектору

Существо **всегда принадлежит сектору, в котором физически находится**. Перетащил
игрока в соседнюю комнату — он теперь принадлежит ей, и дальнейшее движение прежней
комнаты его уже не утащит. При этом существа внутри сектора **двигаются вместе с ним** —
так удобно переставлять комнаты целиком.

### 10.6. Копирование

`Ctrl+C` / `Ctrl+V` вставляет копии **с сохранением кода**: три скопированных `C001`
остаются тремя `C001`. Копии получают новые `uid`, новые идентификаторы геометрии и
встают со смещением к текущей позиции курсора (с привязкой к сетке).

## 11. Лифты

Лифт привязан к сектору; у него есть этажи и кривая движения.

**Создание.** Инструмент «Лифт» (`E`) → клик по сектору. Если лифта в этом секторе не
было — он создаётся, и в секторе появляется фантом этажей. Повторный клик просто
выбирает существующий лифт.

**Этажи.** Список этажей — в левой панели «Кривая лифта»:

* **Нулевой этаж — это сам сектор лифта** (отдельной точкой не хранится). Именно к нему
  можно привязать «ключик», опускающий лифт на дно.
* Новый этаж — **ПКМ по пустому месту** или по чужому сектору, либо кнопка
  «+ Этаж» в панели.
* Выбранный этаж двигается **стрелками** или перетаскиванием в режиме «Выбор».
* Имя этажа — до 3 символов (пишется прямо в списке).

**Кривая.** `sin` (синусоида), `lin` (линейная), `cus` (кастомная) + период `Sec`.
График рисуется в панели.

**Привязки к существам.** Кнопки `⊕` / `✂` в списке этажей:

* **вызывалка** этажа — существо-терминал, которое вызывает лифт на этот этаж;
* **ключик нулевого этажа** — существо, которое опускает лифт на нулевой этаж.

Правило: **привязка живёт, пока на карте есть хоть одно существо с таким кодом.** Удалил
одно из трёх `A001` — привязка цела (код ещё есть). Исчез последний носитель — привязка
снимается автоматически. Меняешь код существа — все его привязки переезжают следом.

**Линии сектора лифта** не участвуют в соединениях — только свободный проход (раздел 9).

В контекстном меню лифта есть переход «Превратить в обычный сектор».

## 12. Триггеры

Инструмент **«Триггер»** (ромбики в тулбаре): зажми ЛКМ и растяни прямоугольник — это и
есть зона триггера, **два ромба по углам** задают её.

* В режиме «Выбор» ромбик двигает **угол**, сам прямоугольник — **целиком**.
* Панель **«Триггеры»** слева задаёт: **ID** (`trigger_01`), **Вид** (внутренний) и
  **Тики** (по умолчанию 5).
* Клик триггером без протяжки просто выделяет уже существующий триггер.

## 13. Проверки карты

Кнопка **«Проверки»** справа в области карты пересчитывает ошибки; они появляются
блоком **над картой**. Что проверяется:

1. **Незамкнутая группа линий** — контур не замкнут, карта не герметична.
2. **Сектор без вершин** (меньше трёх точек или потерянные точки).
3. **Нет игрока `A000`** — при выгрузке в файл редактор сам добавит наблюдателя в (0,0),
   но лучше поставить игрока руками.
4. **Битый код существа** — неверный формат; рядом появляется кнопка **✕**, она
   перевыдаёт код, сохранив позицию существа.

Дубликаты кодов **ошибкой не считаются** (см. раздел 10.2).

## 14. История и буфер обмена

* Один жест = один шаг отмены: протяжка, вставка, удаление — это всё один шаг, а не
  нажатия по клавишам.
* В стеке держится **100 шагов** (`HIST_LIMIT`).
* `Ctrl+Z` — отменить, `Ctrl+Y` или `Ctrl+Shift+Z` — повторить.
* Буфер хранит точки, линии, сектора, существа, триггеры и лифты.
* Вставка идёт со смещением к позиции курсора с привязкой к сетке.

## 15. Сохранение, загрузка, выгрузка

**Автосохранение.** Редактор пишет карту в `localStorage` браузера после каждого
изменения (вместе с позицией камеры). При следующем открытии карта восстанавливается
сама. Если запись не удалась (например, переполненное хранилище), при закрытии вкладки
появится предупреждение браузера.

**Загрузка карты** — кнопка в тулбаре. Принимает:

* текстовый `.vls`;
* JSON-проект (файл, начинающийся с `{`), включая позицию камеры.

**Выгрузка карты** — кнопка рядом. Скачивает файл `<имя карты>.vls` (имя задаётся в
панели «Карта»). Перед записью выполняется три вещи:

1. экспорт идёт по **снапшоту** — рабочая сессия не трогается;
2. связи линий лифтов в файл не пишутся (остаются только свободные проходы);
3. если на карте нет игрока — добавляется **наблюдатель `A000` в (0,0)** (только в файл).

Перед выгрузкой стоит нажать **«Проверки»** и убедиться, что блок предупреждений пуст.

## 16. Формат файла `.vls`

Текстовый файл. Поля разделены **запятыми**, секции — заголовки в квадратных скобках,
строки на `//` — комментарии. Парсер толерантен: пропущенные поля и битые строки просто
пропускаются.

Так выглядит начало реального файла:

```text
// VLS MAP v1 (.vls)
// Vertex Landscape System — экспорт редактора

name = map01
version = VLS.1
units_per_cell = 40

[vertices]
// id, x, y
1,0,0
2,40,0

[lines]
// id, vertexA, vertexB, texture, flags
// flags: 0 = стена, 1 = стена сектора, 2 = портал/соединение, free = свободный проход, step = стык лифта
1,1,2,wall_01,0

[sectors]
// id, vertices(v:id:id...), floor_tex, wall_tex, height, flags, offset_x, offset_y,
// stone, fragile, close, finish, things(id:type:x:y:slot:name;...)
1,v:1:2:3:4,floor_01,wall_01,128,0,0,0,0,0,,,thingsC001:C001:40:40:1:Враг

[connects]
// id, line_id, line2_id

[things]
// id, type, name, x, y, slot, sector_id
C001,C001,Враг,40,40,1,1

[triggers]
// id, tid, type, ticks, x1, y1, x2, y2
1,trigger_01,inner,5,10,10,50,50

[lifts]
// id, sector_id, curve, sec, zero[:type] | floor(x:y:name[:caller_id[:caller_type]])
1,2,sin,3,-|0:-80:1:C001:C001

[summary]
vertices=4
lines=4
sectors=1
things=1
idc=20
```

Тонкости, о которых стоит знать:

* **Существа пишутся дважды**: и в inline-поле своего сектора (`things=…`), и в секции
  `[things]`. При чтении это одна и та же запись — дубль снимается по паре
  «код + позиция», а **не по одному коду** (иначе бы повторы карты схлопнулись в одно).
* **Внутренняя метка `uid` в файл не пишется.** В файле лежит только код — он и есть
  контракт с движком. `uid` выдаётся заново при каждой загрузке.
* Разделители `,;:|` в текстовых полях (имя, тип) заменяются на пробел — иначе ломается
  формат.
* `summary/idc` хранит счётчик идентификаторов, чтобы новые объекты не пересекались со
  старыми.
* Читает файл не редактор, а **движок игры**, и он опознаёт существо по коду — поэтому
  в `[things]` спокойно лежат одинаковые коды.

## 17. Мелочи и подсказки

* `Shift` — универсальная клавиша точности: отключает привязку при установке и даёт шаг
  в 1 юнит при перемещении.
* `F12` → Console — там тот же журнал, что и в левой колонке.
* **Сброс вида** возвращает камеру в (0,0) с масштабом 100 %.
* «Очистить журнал» чистит только лог, карту не трогает.
* «Очистить всех существ» удаляет всех существ (необратимо, но есть отмена).
* Бокс/гладкие углы возвращают предыдущий инструмент сами — не нужно переключаться вручную.
* Выбор языка хранится в браузере и переживает перезапуск.
* Кнопка VLS Wiki пока показывает заглушку.
* Всё, что происходит с картой, дублируется в журнал и в консоль — если что-то
  «сделалось само», это обычно видно там.

## 18. Футажи: что снять в редакторе

Ниже — список скриншотов для документации. Для каждого расписано, **что нужно сделать в

Правила:

### 14. Панель предупреждений («Проверки»)

**Что сделать:**

1. Сначала сделай ошибку: например, инструментом `S` набери точки и **не замыкай**
   контур (нажми `Esc`, чтобы не создавать сектор), либо удали игрока через ПКМ →
   «Удалить».
2. Нажми **«Проверки»** справа в области карты.
3. Сними блок предупреждений **над картой** — там должны быть строки с `⚠`.

**Что должно быть на снимке:** красный/жёлтый блок с текстом ошибок поверх карты.

**Скриншот:** ![Предупреждения проверок](14-checks.png)

---

### 15. Журнал действий

**Что сделать:** выполни 3–4 действия подряд (поставить точку, провести линию, создать
сектор, поставить существо) и сними левый раздел **«Журнал»** — в нём появится лента
записей с подробностями (например, «Линия L5 создана: V1→V2»).

**Что должно быть на снимке:** несколько строк журнала и кнопка «Очистить журнал».

**Скриншот:** ![Журнал действий](15-log.png)

---

### 16. Файл `.vls` в текстовом редакторе

**Что сделать:**

1. Нажми **«Выгрузить карту»** в тулбаре — файл сохранится.
2. Открой его в Блокноте (или любом текстовом редакторе).
3. Сними верхнюю часть файла: шапку `// VLS MAP v1 (.vls)`, строки `name = …`,
   `units_per_cell = 40` и первые секции `[vertices]`, `[lines]`, `[sectors]`.

**Что должно быть на снимке:** читаемый текст формата с секциями в квадратных скобках.

**Скриншот:** ![Файл .vls в блокноте](16-vls-file.png)
